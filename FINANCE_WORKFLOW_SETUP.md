## What leaders can do

- Any active Pack member can submit their own Item, Date, **cost deleted** or **deposit added**, category, optional event, notes, and a restricted Google Drive receipt link. They see only their own requests.
- Admin/Cubmaster and Treasurer see all requests and receive in-app notices. Either can approve their own submission. The audit records the actor, action and time. A reviewer records a unique bank/payment reference to verify payment before posting.
- A reviewer explicitly confirms the final post. The trusted Edge Function sends the canonical database request to a Pack-account Apps Script bridge, which appends exactly one row to the reviewed native Google Sheet. The PackOps ID in column G makes retries idempotent. An approved request does not itself move money.
- A posted row contributes to budget and linked event actuals, and to the current cash balance. A reviewed Sheet refresh imports Courtney's manual entries. Classified restricted Scout funds and transfers are excluded from Pack operating revenue; popcorn operating income stays zero.

## Apply after branch review

1. Take a current encrypted PackOps backup and use the normal independent Supabase backup process. Confirm which migrations have been applied, then run missing migration `supabase/migrations/202610130008_transaction_workflow.sql` in Supabase SQL Editor after 001-007. Apply `202610140009_family_invitation_note.sql` before deploying the updated family function. These are additive; they do not edit existing user records. Test Den Leader, Treasurer, Admin, outsider and suspended-user access against the actual project.
2. Deploy `supabase/functions/finance-workflow` and `supabase/functions/leader-invite`. These functions validate the caller's Supabase session and active Pack membership themselves; use `supabase functions deploy finance-workflow --no-verify-jwt` and `supabase functions deploy leader-invite --no-verify-jwt` to allow the public publishable-key transport. Keep the Supabase service-role key server-side only. The existing `family-rsvp` function must also be deployed for RSVP email/link creation.
3. Under the **Pack** Google account, install `integrations/ledger-bridge.gs` in Apps Script as a web app executing as that account. Review its source, spreadsheet ownership and access policy. Set private script properties `PACK_ID`, `BRIDGE_SECRET` (random, at least 32 characters), and `LEDGER_TARGETS_JSON`, e.g. `{"2026-27":{"spreadsheetId":"1d9_8y2fWBwj4wOXIZcsWsFQXYRoGj3ShOJgPwWL3C00","sheetName":"Sheet1","headerRow":1}}`. The script's web-app access must permit the server's signed call; the HMAC and exact Pack ID protect posting, so do not share the secret or use the script URL as a public user interface.
4. Set private Supabase Edge Function secrets `LEDGER_BRIDGE_URL` (the reviewed `/exec` URL) and the same `LEDGER_BRIDGE_SECRET`. Optional email requires a verified sender plus `RESEND_API_KEY`, `RSVP_FROM_EMAIL`, `PUBLIC_SITE_ORIGIN` and `PUBLIC_SITE_PATH`. Provider acceptance is reported separately from inbox delivery. Never place these values in frontend code, GitHub Actions variables printed in logs, a chat message, or the public repository.
5. On a test project/native Sheet, submit a fictional expense as a Den Leader; check both reviewer notices, approve (including self approval), verify a unique payment reference, and post. Repeating Post must return the same PackOps ID and row. Refresh the official ledger snapshot and confirm one expense in the event and budget actuals. Check restricted funds remain outside Pack operating revenue. Try an unauthorized direct table write and verify RLS denies it. Verify invitation mail only if a provider is configured.
6. Run `npm.cmd run check:live` (Windows PowerShell) to check that the Finance table and three functions exist. Then perform the authorized tests above: the endpoint check cannot prove RLS, email delivery or Sheet access. Publish reviewed frontend changes only after the live services are ready. Merging may update GitHub Pages; coordinate that production release separately.

If the bridge or sender is not configured, PackOps reports that clearly. The app will not claim that a request reached the ledger or an email reached an inbox. A server timeout after the Sheet accepted a row should be retried with the **same** transaction ID and reconciled against column G; never submit a second request to recover it.

Encrypted PackOps backups include a readable archive of the authorized user's transaction requests, audit and notices; restoring a local backup does **not** overwrite these protected Supabase tables or the official Sheet. Retain an independent database backup for disaster recovery. Event attachments selected from a phone are saved on that device only; upload them separately to a restricted Drive folder for sharing.
